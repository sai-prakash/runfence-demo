Stop unsafe or runaway agent tool calls before they hit the world.

RunFence is a thin wrap around write tools — hard per-run budgets, pre-action freshness, and human approval for irreversible actions.

Early design-partner stage. Confirmed customers: 0. No enterprise logos claimed.

View three demos Design-partner waitlist

Problem

  • Agents retry / loop and burn tokens (public cost postmortems).
  • Tools act on stale context after the world moved.
  • Irreversible tools (refund, book, send) fire without a human gate.

Framed from public research — not from invented “Company X” case studies.

Three gates

BUDGET_EXCEEDED

Hard kill when the run crosses a step / token ceiling — not a warning.

npm run demo:budget

STALE_EVIDENCE

Block writes if declared evidence went stale after the snapshot.

npm run demo:stale

NEEDS_APPROVAL

Hold irreversible tools until a human approves once.

npm run demo:approval

Run the local kit from the demo README; see github.com/sai-prakash/runfence-demo.

What’s included

  • Fake MCP fixtures (refund_customer, book_slot) — not live Stripe/booking.
  • Middleware wrap + JSONL audit of allow vs block.
  • One-command demos for the three reason codes.

What’s not

  • SLA, SSO, multi-tenant cloud, prod liability.
  • Full agent framework, voice agents, browser shopping bots.
  • Real money movement in the demo path.
